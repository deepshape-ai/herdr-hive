# Bee–Hive protocol v1

Transport: SSH public-key authentication, verified server host key. Each device
uses one identity. Native consumers use OpenSSH; Bee uses the Go SSH library.
Control JSON is UTF-8 and limited to 65,536 bytes. SSH library limits apply before
application parsing as well. All integers and field names below are part of v1.

## SSH usernames

| Username | Role |
| --- | --- |
| `bee` | Register an outbound publisher transport |
| `hive` | Execute the directory query `list --json` |
| `s-` followed by 24 lowercase hex digits | Route native Herdr requests to one online share |

All users must present a registered key. No password, interactive shell, PTY,
SFTP, SCP, TCP forwarding, Unix forwarding, environment forwarding or SSH agent
forwarding is accepted at Hive. Native Herdr's local TUI does not require a remote
SSH PTY; it uses an exec channel carrying the binary client protocol.

## Registration

Bee sends one SSH global request `publish@herdr-hive/v1`, requesting a reply:

```json
{
  "version": 1,
  "name": "Workstation",
  "shares": [
    {"key": "0123456789abcdef0123456789abcdef", "label": "project"}
  ]
}
```

The key is generated once for an explicitly selected manual rule. Maximum 32
shares per device; duplicate or malformed keys are rejected. Display names and
labels contain 1–128 UTF-8 bytes without control characters. A device can have
only one active publication transport. Registration is all-or-nothing.

Success payload is a JSON array containing each key, label, collision-resolved
`name` and `id`. The ID is `s-` plus the first 12 bytes of SHA-256 over
`SSH-SHA256-fingerprint + NUL + rule-key`, encoded as lowercase hex. It is a
resource identifier, not a bearer token. Failure has SSH success=false.

A lost connection removes all its shares and closes attached channels. Turning
off publication needs no separate revocation protocol: closing the owning
transport revokes its live routes. No offline directory entry or content is kept.

## Reverse operations

Hive opens `bee-stream-v1` channels on the registered Bee connection. Extra data:

```json
{"key":"0123456789abcdef0123456789abcdef","kind":"client"}
```

| Kind | Channel response |
| --- | --- |
| `client` | Full-duplex native Herdr client socket bytes |
| `check` | Open and close the selected client socket; empty successful response |
| `status-client` | Output of fixed local `herdr status client --json` |
| `status-server` | Output of fixed local `herdr status server --json` against the selected socket |
| `platform` | Two lines: local OS and architecture in Herdr's expected uname format |

Unknown keys/kinds or replaced/unavailable sockets reject channel opening. Bee
never receives a caller-selected filesystem path or shell command. Metadata is
computed before accepting the channel, so local operation errors are not reported
as successful empty output. Native bytes are never JSON-wrapped or retained.

SSH EOF/close propagates across the stream. A closure cancels the other copy
direction. There is no application replay queue, retry of input, compression or
unbounded transcript buffer. `keepalive@openssh.com` supports liveness checks.

## Native adapter

`/bin/sh -s` exec requests have a bounded stdin payload and deadline. The adapter
recognizes known bootstrap bodies without invoking a shell. Discovery reports a
virtual `/herdr` path. Fixed status and `remote-client-bridge` requests map to the
operations above. Arbitrary commands, install scripts and `--remote-session`
retargeting are rejected. See `hive/internal/herdr/adapter.go` for the complete
allowlist and upstream discovery hashes.

## Evolution

Hive and Bee versions are independent. Keep the v1 channel/request names for
backward-compatible additions. A breaking wire change uses a new versioned
request/channel and must coexist or fail explicitly; never reinterpret a v1
field or broaden selected resources. Native Herdr adapter compatibility is a
separate dimension from the Bee–Hive protocol version.
